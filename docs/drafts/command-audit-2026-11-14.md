## Surprises

- **`debug capture-arrival-golden` is likely destructive now.** The golden file is shared by both assets, but the command only collects the selected asset's datasets and then rewrites the whole file. Running it would quietly drop the other asset's pinned arrivals. This is from reading the code; I did not run it.
- **`debug build-warehouses` writes to the database despite being described as a DuckDB step.** It stages every arrival into the PostgreSQL supply DB, which is exactly what `mothman supply load` already does with better reporting.
- **`github sync-tickets` doesn't check whether ticketing is switched on.** It never reads `env.ticketing`, so run by hand it would open per-dataset issues in keithamoss/data-poc (the `ticket_repository` in both assets' `data-asset.yaml`, line 99) from any environment, sandbox included. It also overlaps the REQ-PIPE-083 reconciler, which says it never touches tickets from the older scheme.
- **The dashboard leaderboard has had no data source since `deploy-pages.yml` was deleted**, which leaves `sync-leaderboard` without a consumer.
- **Deleting the equivalence harness is bigger than deleting the CLI commands.** `tests/equiv_support.py` builds four non-equivalence on-demand tests (checkpoints, replay clock, bootstrap equivalence, kept-routes) on top of `qa_tools/common/equivalence.py`'s snapshot and diff code. The `fetch-depth: 0` lines in `test.yml` exist only for this harness.
- **Stale "committed qa_results/" wording is still around:**
  - the `cli/debug.py` module docstring (lines 14-24), which warns that the run-* commands overwrite committed `qa_results/` files;
  - `dashboard rebuild`'s console message (`cli/dashboard.py:273`);
  - the `debug changelog` help;
  - README.md:46-48, which still lists github "acceptance" sync (retired) and `build-warehouses`.
- **Not confirmed:**
  - whether `ensure_schema` in `debug changelog` issues DDL on an existing database;
  - a real end-to-end run of equivalence capture, sync-tickets or build-warehouses.
